# Профиль — задача 18070

Задача: https://ai.nsu.ru/issues/18070
Строится от master. Экран /profile встроен в MobileShell. Палитра, типографика, кнопки и поля соответствуют существующим экранам приложения: #101914, белый текст, лаймовые акценты. Figma используется для структуры, а не для светлой темы.

## Границы задачи и сверка со стори

| Требование стори | В задаче 18070 |
| --- | --- |
| Открытие собственного профиля и общие поля | Реализовано на mock-данных: имя, фамилия, дата рождения, пол, город, описание; плейсхолдер аватара из инициалов |
| Данные ATHLETE | Рост, вес, уровень подготовки, предпочтение RX/scaled |
| Данные TRAINER | Специализации, стаж, методика |
| «Редактировать профиль», форма, «Сохранить» | Реализовано, после успеха отображаются сохранённые значения и уведомление |
| Обязательные поля | Имя и фамилия; пробелы не считаются заполнением |
| Числовая валидация | Рост — положительное целое; вес — положительное число с точностью до двух знаков; стаж — неотрицательное целое |
| Будущая дата рождения | Ошибка и подсветка поля, запрос не отправляется |
| Отмена | Закрывает форму без изменения сохранённых данных |
| Загрузка, сохранение, ошибки | Реализованы, есть повторная попытка, форма сохраняет введённые значения при ошибке; повторное сохранение блокируется |
| Реальная аутентификация и наличие профиля на сервере | Предусловия стори; в этой задаче используется mock существующего пользователя |
| Реальные GET/PATCH профиля | Отдельная задача 18071 после готовности backend 18069 |
| Загрузка, замена, удаление аватара; JPEG/PNG/WEBP до 5 МБ | Отдельная задача 18073 совместно с backend 18072. В этой ветке нет файлового ввода и изменения avatarKey |

Числовые верхние границы пока соответствуют типам текущей backend-модели: heightCm/experienceYears — PostgreSQL integer (максимум 2147483647), weightKg — numeric(6,2) (максимум 9999.99). Более узкие бизнес-диапазоны в предоставленной стори и найденных моделях не объявлены; перед подключением API их нужно согласовать. Текстовые ограничения: имя/фамилия — 100, город — 120, описание/специализации/методика — 5000 символов, как в backend-моделях.

## Контракт и mock

Полный будущий ProfileResponse пока не опубликован: старый UserProfileResponse содержит только id, email, displayName. Тип src/features/profile/types.ts предварительный, составлен по UserProfile, AthleteProfile, TrainerProfile и AccountResponse из backend-ветки feature/auth-and-profiles. При появлении согласованного DTO нужно сверить названия и вложенность в адаптере.

Общие поля: id, email, roles, activeRole, firstName, lastName, birthDate (YYYY-MM-DD или null), gender (MALE/FEMALE/OTHER или null), city, about, avatarKey. athleteProfile: heightCm, weightKg, fitnessLevel (BEGINNER/INTERMEDIATE/ADVANCED), rxPreference (RX/SCALED). trainerProfile: specializations (строка), experienceYears, methodology. Необязательные значения — null. В обновление входят только общие редактируемые поля и блок активной роли; email, id, права и avatarKey не изменяются.

Mock API изолирован от компонентов. Данные живут в памяти до перезагрузки страницы, сохраняются при переходах внутри приложения. Выбор роли относится к mock-профилю; при объединении с ролевой навигацией её источником должен стать общий auth-контекст. Ни реальные запросы к backend, ни файлы не отправляются.

## Проверки

npm test, npm run lint, npm run build.

Dev-сценарии для ручной проверки:
- /profile — профиль атлета, можно выбрать тренерский вариант;
- /profile?profileScenario=load-error — ошибка загрузки;
- /profile?profileScenario=save-error — ошибка сохранения;
- /profile?profileScenario=slow — медленная загрузка/сохранение.

В production параметры сценариев игнорируются. История изменений, удаление аккаунта и чужие профили не входят в задачу.
